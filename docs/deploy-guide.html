Mac mini デプロイガイド

Agent Command Center を Mac mini で 24時間稼働させるための手順

macOS 14+ Node.js 20+ PostgreSQL 16 PM2
① 前提条件 ② DB ③ 環境変数 ④ ビルド ⑤ PM2起動 ⑥ 自動起動 ⑦ 動作確認
STEP 1 — 前提条件

必要なソフトウェアをインストール

Mac mini に SSH またはローカルでターミナルを開いて実行します。

# Homebrew（未インストールの場合）
/bin/bash -c "$(curl -fsSL https://raw.githubusercontent.com/Homebrew/install/HEAD/install.sh)"

# Node.js 20 LTS
brew install node@20
echo 'export PATH="/opt/homebrew/opt/node@20/bin:$PATH"' >> ~/.zshrc
source ~/.zshrc

# pnpm（パッケージマネージャ）
npm install -g pnpm

# PostgreSQL 16
brew install postgresql@16
brew services start postgresql@16
echo 'export PATH="/opt/homebrew/opt/postgresql@16/bin:$PATH"' >> ~/.zshrc
source ~/.zshrc

# PM2（プロセスマネージャ）
npm install -g pm2

# バージョン確認
node -v && pnpm -v && psql --version && pm2 -v
ℹ️
Apple Silicon (M1/M2/M3) の場合、Homebrew は /opt/homebrew/ にインストールされます。Intel Macは /usr/local/ です。
STEP 2 — リポジトリのセットアップ

コードを Mac mini に配置

# プロジェクトをコピー（開発機からrsyncで転送する場合）
rsync -avz --exclude='node_modules' --exclude='.next' --exclude='.env' \
  /path/to/agent-command-center/ \
  macmini@192.168.x.x:~/agent-command-center/

# Mac mini 側で依存インストール
cd ~/agent-command-center
pnpm install
✅
Git リポジトリがある場合は git clone でも OK。.env ファイルは必ず手動で作成してください（gitには含めないこと）。
STEP 3 — データベースのセットアップ

ローカル PostgreSQL を初期化

# セットアップスクリプトを実行（ユーザー・DB作成 + スキーマ適用）
cd ~/agent-command-center
bash scripts/setup-db.sh

スクリプトが実行すること：

  • ✓ pathway ユーザー作成
  • ✓ pathway データベース作成
  • ✓ pnpm drizzle-kit push でスキーマ適用
# 接続確認
psql postgresql://pathway:pathway@localhost:5432/pathway -c "\dt"
⚠️
Mac mini を再起動した後も PostgreSQL が自動起動するよう、brew services start postgresql@16 で launchd 登録されていることを確認してください。
STEP 4 — 環境変数の設定

.env ファイルを作成

cp .env.example .env
nano .env  # または vim .env

以下の項目を必ず設定してください：

変数名 説明 必須
ANTHROPIC_API_KEY Anthropic APIキー（console.anthropic.com で取得） 必須
DATABASE_URL postgresql://pathway:pathway@localhost:5432/pathway 必須
CRON_SECRET cronエンドポイントの認証トークン（32文字以上のランダム文字列） 必須
APP_AUTH_EMAIL ログイン用メールアドレス 必須
APP_AUTH_PASSWORD ログイン用パスワード 必須
APP_SESSION_SECRET セッション暗号化キー（32文字以上） 必須
NEXT_PUBLIC_APP_URL http://localhost:3000（Mac mini のローカルIP でもOK） 必須
LARK_WEBHOOK_URL_OPS Lark 通知用 Webhook URL 任意
ANTHROPIC_ENABLE_WEB_SEARCH 1（リサーチエージェント用の web 検索を有効化） 推奨 
# ランダムなシークレット生成（例）
openssl rand -base64 32
STEP 5 — 本番ビルド

Next.js アプリをビルド

cd ~/agent-command-center
pnpm build

# ビルド成功を確認
ls -la .next/
ℹ️
ビルド時間は Mac mini のスペックにより 2〜5 分ほどかかります。Route (app) の一覧が表示されれば成功です。
STEP 6 — PM2 でプロセス起動

アプリとスケジューラーを起動

cd ~/agent-command-center

# ecosystem.config.js で定義された全プロセスを起動
pm2 start ecosystem.config.js

# 起動確認
pm2 list

# ログ確認
pm2 logs pathway-agent --lines 50

起動されるプロセス：

プロセス名内容スケジュール
pathway-agent Next.js アプリ本体（ポート3000） 常時起動
scout-cron 海外商品スカウト実行 毎日 6:00 / 18:00
learn-cron 承認パターン自己学習 毎日 7:00 / 19:00 
# 手動でスカウトを今すぐ実行したい場合
curl -s http://localhost:3000/api/cron/scout \
  -H "Authorization: Bearer $CRON_SECRET"
STEP 7 — Mac mini 自動起動設定

再起動後も自動で復旧するよう設定

# PM2 の自動起動スクリプトを生成（表示されたコマンドをコピーして実行）
pm2 startup

# 例: 上記コマンドが表示する内容を実行（ユーザー名は環境による）
sudo env PATH=$PATH:/opt/homebrew/opt/node@20/bin pm2 startup launchd -u $(whoami) --hp $HOME

# 現在の PM2 プロセスリストを保存
pm2 save
✅
これで Mac mini が再起動・電源断から復旧した後も、PM2 が自動でアプリとスケジューラーを再起動します。

代替手段（PM2 なしで launchd のみ使う場合）：

# launchd plist を LaunchAgents にコピー
cp ~/agent-command-center/com.pathway.scout.plist \
  ~/Library/LaunchAgents/

# 有効化
launchctl load ~/Library/LaunchAgents/com.pathway.scout.plist
STEP 8 — 動作確認

すべてが正常に動いているか確認

# 1. プロセス状態確認
pm2 list

# 2. アプリにアクセス
open http://localhost:3000

# 3. ヘルスチェック
curl -s http://localhost:3000/api/health | python3 -m json.tool

# 4. スカウト手動実行テスト
curl -s "http://localhost:3000/api/cron/scout" \
  -H "Authorization: Bearer $(grep CRON_SECRET .env | cut -d= -f2)"

# 5. ログ監視
tail -f logs/cron.log

# 6. DB 確認
psql postgresql://pathway:pathway@localhost:5432/pathway \
  -c "SELECT count(*) FROM products;"
よくある問題

トラブルシューティング

❌ Port 3000 が使用中
lsof -ti:3000 | xargs kill -9 でポートを解放してから再起動してください。 または .env の PORT=3001 に変更。
❌ PostgreSQL に接続できない
brew services list | grep postgresql で起動状態を確認。停止していれば brew services start postgresql@16 で起動。 DATABASE_URL のパスワードも確認。
❌ pnpm build でエラー
node -v が 20 以上か確認。rm -rf .next && pnpm build でキャッシュクリア。 .env の必須変数が設定されているか確認。
❌ Anthropic API rate limit エラー
.env で SCOUT_SCORING_CONCURRENCY=1 に下げる。 または MINIMAL_SCOUT_LLM_MAX=5 で1回あたりの処理数を減らす。
❌ cron が実行されない
pm2 logs scout-cron でログ確認。 CRON_SECRET が .env に設定されているか確認。 手動で bash scripts/run-cron.sh を実行してエラーを確認。
